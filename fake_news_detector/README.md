# 基于 DeepSeek 隐含语义增强的细粒度虚假新闻检测系统

本项目在原论文（《基于大语言模型隐含语义增强的细粒度虚假新闻检测方法》）基础上进行改进，
适用于中国国内新闻数据集，全系统仅依赖 DeepSeek 一个模型。

---

## 项目结构

```
fake_news_detector/
├── config.py           # 全局配置：API、模型参数、三级信源列表、隐含信息类型
├── llm_client.py       # DeepSeek 调用封装（普通推理 + 联网搜索）
├── implicit_types.py   # 六类隐含信息的专门提示词模板 + 通用事件提示词
├── retrieval.py        # 基于 DeepSeek 联网搜索的国内新闻检索
├── authority_check.py  # 三级信源核查（短路 / 佐证注入 / 参考）
├── event_extractor.py  # 三层事件抽取（主干事件 / 次要事件 / 隐含信息）
├── dual_model.py       # DeepSeek 两阶段交叉验证判断（初判 + 批判复核）
├── detector.py         # 主流程编排
├── main.py             # CLI 入口（单条 / 批量 / 交互三种模式）
└── requirements.txt    # 依赖（仅 openai 一个库）
```

## 相较原论文的四项核心改进

### 改进一：时效性新闻处理

- 通过关键词（"今日"、"突发"、"刚刚"等）自动识别时效性新闻，启用严格时效过滤（7天内）；
- DeepSeek 联网搜索优先命中辟谣平台和权威媒体的近期内容；
- **短路机制**：一旦找到与原新闻**完全一致**（非相似）的辟谣平台记录或权威媒体官方报道，
  且置信度为高/中，则直接输出结论，不再进行后续三层分析，节省大量 API 调用。

### 改进二：DeepSeek 两阶段交叉验证（替代双模型协商）

原论文使用两个不同模型（DeepSeek + Qwen）互相辩论；本系统改为 **DeepSeek 单模型，
通过角色切换进行两阶段验证**，效果相当，成本减半：

| 阶段 | 角色 | 任务 |
|------|------|------|
| 第一阶段（初判） | 正向推理员 | 基于事件描述与检索信息，正向给出判断结论 |
| 第二阶段（批判复核） | 挑剔主编 | 主动寻找初判的逻辑漏洞、确认偏误、被忽视的矛盾点 |

**协商逻辑**：
- 两阶段结论**一致** → 合并理由，直接输出；
- 两阶段结论**不一致** → 进入追加复核循环（最多 `MAX_REVIEW_ROUNDS` 轮，默认2轮）：
  - 核查员针对主编质疑进行反驳或修正；
  - 若追加复核与复核阶段一致 → 复核意见确认，输出复核结论；
  - 若追加复核与初判一致 → 初判得到确认，输出初判结论；
- 达到上限仍未一致 → **并列输出初判与复核各自的结论与理由**，由用户判断。

### 改进三：隐含信息精细建模（六类型）

原论文隐含信息为笼统的单一类型；本系统定义了六种独立类型，每种配备专门的角色和提示词：

| 类型键名 | 中文名 | 检测重点 |
|----------|--------|----------|
| `presupposition` | 预设信息 | 新闻默认成立、未经证明的前提假设 |
| `implicature` | 会话含义 | 字面表达之外传递的隐含意图 |
| `framing_bias` | 框架偏向 | 选择性叙事、立场倾向、议程设置 |
| `factual_gap` | 事实缺口 | 刻意省略或回避的关键信息 |
| `emotion_manipulation` | 情绪操控 | 煽动恐惧、愤怒、同情的措辞手段 |
| `causal_fallacy` | 因果谬误 | 后此谬误、相关性混淆、单一原因谬误 |

### 改进四：三级信源可信度体系（新增）

**解决的问题**：原系统仅有"权威媒体"和"其他"两档，对于高校官网发布的录取
喜讯、政府部门发布的通知公告、科研机构发布的成果报道等**未进入全国性权威媒体
但本身可信的官方内容**，既不能直接短路（可能误判），也不应完全忽视（会损失有
价值的佐证）。

**核心设计原则**：**信源可信度决定证据权重，不等于内容免检。**

| 级别 | 信源类型 | 触发条件 | 处理方式 |
|------|----------|----------|----------|
| 第一级 | 权威媒体（央视/新华网等）+ 辟谣平台 | 完全一致 + 置信度高/中 | **直接短路**，输出最终结论 |
| 第二级 | 可信官方信源（edu.cn / gov.cn 等） | 找到相同内容的原文 | **不短路**，将原文注入 `verified_facts`，在后续所有分支判断中作为有利佐证 |
| 其他 | 普通媒体、自媒体、未认证账号 | — | 仅作普通检索参考，不加分 |

**第二级信源的判断安全性**：

```
场景一：学校官网发布真实录取/获奖喜讯
  → 搜到 edu.cn 原文 → 注入 verified_facts
  → 三层分析时 DeepSeek 感知到"官方已发布相同内容"
  → 各分支核查无矛盾 → 大概率判定真实 ✅

场景二：小型自媒体发布假新闻
  → 不在任何可信列表 → 原文不加分
  → 三层分析正常进行 → 造假内容在分支核查中被发现 ✅

场景三：官方账号发布虚假公告（如伪造通知）
  → 即便搜到 edu.cn 原文，佐证注入
  → 三层分析独立核查：检索到"官方并无此信息"的矛盾
  → 虚假信息在次要事件/隐含信息分支中被识别 ✅
```

第二级信源查找结果会体现在 `DetectionResult` 的新字段中：
- `trusted_source_injected`：是否注入了官方信源佐证
- `trusted_source_name`：信源名称（如：北京大学官网）
- `trusted_source_url`：信源链接

## 完整检测流程

```
原始新闻文本
      │
      ▼
┌────────────────────────────────────────────────────────┐
│ Step 0  三级信源核查                                    │  ← DeepSeek 联网搜索
│                                                        │
│  ┌─ 第一级：权威媒体 & 辟谣平台 ─────────────────────┐ │
│  │  找到完全一致记录？置信度高/中？                   │ │
│  │  是 → 直接短路输出结论（流程终止）                 │ │
│  │  否 → 进入第二级检测                              │ │
│  └────────────────────────────────────────────────────┘ │
│                                                        │
│  ┌─ 第二级：可信官方信源（edu.cn / gov.cn 等） ───────┐ │
│  │  找到相同内容的原文？                              │ │
│  │  是 → 将原文注入 verified_facts（不短路，继续）    │ │
│  │  否 → 继续，verified_facts 为空                   │ │
│  └────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────┐
│ Step 1  三层事件抽取                 │
│  1a. 主干事件（5W1H，两次调用校验）  │
│  1b. 次要事件（多轮迭代，最多5个）   │
│  1c. 隐含信息（六类型，各自抽取）    │
└─────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────┐
│ Step 2  各分支独立检索               │  ← DeepSeek 联网搜索
│  主干事件 → 检索外部知识             │
│  每个次要事件 → 检索外部知识         │
│  每类隐含信息 → 检索外部知识         │
└─────────────────────────────────────┘
      │
      ▼
┌──────────────────────────────────────────────────────────┐
│ Step 3  层级递进式两阶段判断                              │
│  每个分支的判断提示词中均含 verified_facts，              │
│  若第二级佐证已注入，DeepSeek 会将其纳入判断依据          │
│                                                          │
│  3a. 主干事件判断                                         │
│      初判 → 批判复核 → 一致则输出 / 不一致则追加复核       │
│      → 判定为虚假？立即终止，输出结论                     │
│      → 判定为真实？作为"已核实事实"传入下一层              │
│                                                          │
│  3b. 次要事件逐一判断（含上一层已核实事实作为背景）         │
│      → 任一次要事件判定为虚假？立即终止                    │
│                                                          │
│  3c. 六类隐含信息各自判断（含上层已核实事实）              │
│      → 累积所有隐含信息结果后统一汇总                     │
└──────────────────────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────┐
│ Step 4  汇总最终结论                 │
│  有≥1个分支为虚假 → 判定【虚假】     │
│  全部分支为真实   → 判定【真实】     │
│  若第二级佐证注入，结论中标注来源    │
└─────────────────────────────────────┘
```

## 环境配置

### 安装依赖

```bash
pip install -r requirements.txt
# 仅需 openai 一个库
```

### 配置 API 密钥

```bash
export DEEPSEEK_API_KEY="your_deepseek_api_key"
```

> **注意**：DeepSeek 联网深度搜索（`search_type="pro"`）为付费功能，
> 请在 DeepSeek 控制台确认已开通，并关注用量。

## 使用方法

### 单条新闻检测

```bash
python main.py --news "新闻正文内容"
```

### 单条检测（JSON 格式输出）

```bash
python main.py --news "新闻正文内容" --json
```


```bash
python main.py
# 输入新闻文本，两次回车确认；输入 quit 退出
```

## 各模块说明

### `config.py` — 全局配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `DEEPSEEK_API_KEY` | 环境变量 | DeepSeek API 密钥 |
| `DEEPSEEK_MODEL` | `deepseek-chat` | 使用的模型（DeepSeek-V3） |
| `TEMPERATURE` | `0.3` | 生成温度，低温保证稳定推理 |
| `MAX_TOKENS` | `2048` | 单次最大输出 token 数 |
| `MAX_REVIEW_ROUNDS` | `2` | 初判与复核不一致时的追加复核轮次上限 |
| `RECENCY_DAYS` | `30` | 检索时优先返回最近N天内容 |
| `STRICT_RECENCY_DAYS` | `7` | 时效性新闻严格过滤天数 |
| `MAX_SEARCH_RESULTS` | `5` | 每次检索最多返回条数 |
| `AUTHORITATIVE_MEDIA` | 见下文 | 第一级：权威媒体域名列表 |
| `FACT_CHECK_PLATFORMS` | 见下文 | 第一级：辟谣平台域名列表 |
| `TRUSTED_OFFICIAL_SOURCES` | 见下文 | **第二级（新增）**：可信官方信源域名列表 |

**扩展第二级信源**：在 `config.py` 的 `TRUSTED_OFFICIAL_SOURCES` 列表中添加域名即可：

```python
TRUSTED_OFFICIAL_SOURCES = [
    "edu.cn",        # 所有中国高校（*.edu.cn）
    "gov.cn",        # 各级政府机构（*.gov.cn）
    "cas.cn",        # 中国科学院
    "cass.cn",       # 中国社会科学院
    # 可继续添加：如 "nmpa.gov.cn"（药监局）等
]
```

### `authority_check.py` — 三级信源核查

新版 `AuthorityCheckResult` 增加了以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `short_circuit` | bool | 第一级命中，直接短路（原有） |
| `verdict` | str | 短路时的判决（原有） |
| `trusted_source_found` | bool | **新增**：是否找到第二级可信官方信源原文 |
| `trusted_source_name` | str | **新增**：信源名称（如"北京大学官网"） |
| `trusted_source_url` | str | **新增**：信源链接 |
| `trusted_source_content` | str | **新增**：原文摘要，注入 verified_facts 用 |

同时内置了**兜底逻辑**：若 DeepSeek 未在结构化结果中识别第二级信源，
但 `citations` 中包含 `edu.cn` / `gov.cn` 等链接，会自动提取并填充。

### `detector.py` — 主流程编排

新版 `DetectionResult` 增加了以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `trusted_source_injected` | bool | **新增**：是否注入了官方信源佐证 |
| `trusted_source_name` | str | **新增**：注入的信源名称 |
| `trusted_source_url` | str | **新增**：注入的信源链接 |

Step 0 执行后，若找到第二级佐证，会在 `verified_facts_list` 头部插入一条
标注为「可信官方信源已找到原文」的条目，这条信息会传入后续每一个分支的判断
提示词中，让 DeepSeek 在推理时将其纳入依据。

若最终判定为真实且存在第二级佐证，`final_reason` 末尾会附注信源来源。

### 其余模块（未改动）

- `llm_client.py`、`implicit_types.py`、`retrieval.py`、`event_extractor.py`、
  `dual_model.py`、`main.py` 与原版完全一致，无需任何修改。

## 注意事项

1. **API 用量**：每条新闻涉及大量 DeepSeek 调用，建议在控制台监控用量；
2. **联网搜索**：`search_type="pro"` 为深度搜索，费率高于普通调用；
3. **短路条件严格**：完全匹配要求较高，相似新闻不会误触发短路；
4. **第二级安全性**：可信官方信源仅作佐证，不跳过三层分析；
   官方账号发布的假内容仍会在分支核查中被识别；
5. **数据集适用**：本系统面向中国国内新闻，检索来源均为国内平台。
